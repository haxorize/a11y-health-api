# Alembic Migration Conventions

## Setup

Alembic is configured with async SQLAlchemy. The `env.py` must use `run_async` with `connectable = create_async_engine(...)`.

Import all models in `env.py` so autogenerate can detect them:
```python
from a11y_health.core.database import Base
from a11y_health.models import *  # noqa: F403
target_metadata = Base.metadata
```

## Creating migrations

```bash
# Autogenerate from model changes
alembic revision --autogenerate -m "add <resource> table"

# Empty migration for manual SQL
alembic revision -m "seed <resource> data"
```

## Migration conventions

- One migration per logical change (don't batch unrelated table changes)
- Message format: verb + object — `"add users table"`, `"add index on scans.url"`
- Always review autogenerated migrations before applying
- Include `down_revision` checks — never skip or reorder

## Applying migrations

```bash
alembic upgrade head      # apply all pending
alembic downgrade -1      # roll back one
alembic history           # view migration chain
alembic current           # show current revision
```

## Data migrations

For seed data or data transforms, use `op.execute()` with raw SQL rather than ORM models (models may change, but migrations are immutable).

## Testing migrations

Verify migrations apply cleanly against an empty database:
```bash
alembic downgrade base && alembic upgrade head
```
