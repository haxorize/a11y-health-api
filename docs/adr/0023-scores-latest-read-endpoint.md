# Latest scores served by a dedicated read endpoint

The dashboard overview needs the latest Score Snapshot for every App and every Brand at once, which the per-entity score-history endpoints only answer N+1. `GET /api/v1/scores/latest?owner_type=...` returns the latest `ScoreSnapshotRead` per entity of one owner type, reusing the same latest-selection as Rollup (`snapshot_at DESC, id DESC`, extracted from `score_snapshot.py`'s rollup queries into the shared `services/_latest_snapshot.py`, not re-derived) so the dashboard's "latest" can never disagree with what rollups aggregate. Embedding a `latest_score` on `AppRead`/`BrandRead` was rejected because those are write-model shapes returned by create/update; a UI-shaped `/dashboard` BFF endpoint was rejected because the API would have to chase every screen redesign; client-side N+1 fan-out was rejected as a degrading floor, not a contract.
