# Typed Classification schema with a compact wire shape

`RuleFindingRead.classifications` is served as a closed typed schema (`standard` enum required; `version`/`level` optional, `level` an A/AA/AAA enum) instead of the open string map it started as, and a model serializer omits absent members so the wire shape stays byte-identical to the stored JSONB (`{"standard": "best-practice"}`, never `"version": null`). Issue #106 proposed plain-string members; the enums were tightened deliberately — values are minted from a fixed server-side token map, so the enum documents reality, and widening it later is a normal contract change through the codegen pipeline. Serializing the model naively was rejected because explicit nulls fail the previously generated UI client's Zod validator (`Record<string, string>`), turning an API-first deploy into a broken findings page; note this narrowing cuts both ways — any future change to this schema (even a widening) breaks already-generated clients until the UI regenerates, so contract edits here are lockstep changes with the UI.

## Consequences

- One canonical Classification shape everywhere: stored JSONB, GIN containment filter targets, and the wire all agree (`Classification.stored()` and the `_omit_none_members` serializer in `models/classification.py`).
- Out-of-vocabulary values in the JSONB column (manual backfill, a future standard) now fail read-side validation instead of passing through — write-side enforcement is a tracked follow-up. — corrected: see Amendments 2026-07-18

## Amendments

**Amended 2026-07-18 (#114):** the follow-up landed, and it changed both halves of the second consequence. The compact shape is now a column guarantee — `_CompactClassifications` (a `TypeDecorator` in `models/rule_finding.py`) validates and dumps every bound value, covering writers and the filter's GIN containment targets alike — and an invalid entry written past that guard (raw-SQL backfill) — one that fails the `Classification` shape — is dropped from reads with a warning instead of failing the page that renders it, matching the codebase's tolerant-read style (unknown tags dropped at ingest, out-of-shape criteria sorting last). `Classification` itself moved to `models/classification.py`, a layer-neutral leaf, so the column type never imports from schemas; `schemas/_tag_parsing.py` still owns parsing and the token vocabulary.

**Amended 2026-08-05:** the vocabulary follows the value object. The token vocabulary — the closed token set, the token↔`Classification` map with its import-time drift guard, the stored-shape mint, and the filter-options enumeration — moves from `schemas/_tag_parsing.py` into `models/classification.py`, for the same reason `Classification` moved here: its consumers (the findings endpoint's query vocabulary, the filter service, the read schema, and the test factories) span layers, and the underscore name was a fiction every one of them had to cross. `models/` wins on the quantified placement argument: putting the vocabulary in `schemas/` would send three of its five production consumers across a seam, and `services/` four. Those five are `api/v1/endpoints/findings.py` (the query vocabulary), `services/rule_finding.py` (the filter and its options), `schemas/rule_finding.py` (the read schema), `models/rule_finding.py` (the `_CompactClassifications` column type), and `schemas/axe_payload.py` (the **Axe Boundary**); `tests/factories.py` imports it too, outside the production count. This record is the keeper of that roster, and `tests/models/test_classification.py` fails when a sixth production importer appears — amended: see Amendments 2026-09-26 (#167) and 2026-09-26 (#166). `_tag_parsing.py` shrinks to the axe-tag ingest adapter, genuinely private to its package, importing the vocabulary from here so query and storage still cannot disagree; the WCAG criterion sort key — criteria, not Classification — moves into its single consumer, the filter service. Rejected: renaming `_tag_parsing` public in place (honest name, wrong seam — cross-layer imports of query vocabulary would still point into the schemas layer, with ingest parsing and query vocabulary behind one interface) and a sibling vocabulary module beside this one (one concept split across two files, and the drift guard's colocation argument would span an import edge). The module's charter is closed: the value object and the closed vocabulary that names it, nothing else. In the same change `services/_scoring_vocabulary.py` is renamed public — the same private-name-with-cross-layer-importers shape, served on the wire, both importers already aliasing the underscore away — with no record of its own because the rename carries no trade-off. — amended: see Amendments 2026-08-05 (#131 review)

**Amended 2026-08-05 (#131 review):** the ingest screen followed the vocabulary, superseding the clause above that has `_tag_parsing.py` importing it. `classifications_in` — the read that names a rule's raw axe tags — sits in `models/classification.py` beside `classification_options`, which does the same job for stored entries: both screen open-ended input against the closed token set and drop what it cannot name, and they were one operation split across two layers — amended: see Amendments 2026-09-26 (#166). `_tag_parsing.py` now imports nothing from here and owns axe tag *syntax* alone — a Category and its WCAG Criteria, the values that have to be read out of a tag's shape. The charter closes around the value object, the vocabulary, the drift guard, and the three reads that vocabulary answers. — amended: see Amendments 2026-09-27 (#177)

**Amended 2026-09-26 (#167):** the production roster is four. The findings endpoint no longer imports the vocabulary: the filter dimensions are declared once, as `FindingFilters` in `schemas/rule_finding.py`, and the endpoint takes that declaration, so the query vocabulary reaches it through the schema rather than directly. The remaining four are `services/rule_finding.py`, `schemas/rule_finding.py`, `models/rule_finding.py`, and `schemas/axe_payload.py`, and `tests/models/test_classification.py` now fails when a fifth appears. Recounted over the four, putting the vocabulary in `schemas/` sends two consumers across a seam and `services/` three, while `models/` sends none, because an import from `models/` crosses no seam: the layer holds the layer-neutral leaves no other layer owns (`docs/architecture.md`, "The layers"). The 2026-08-05 count left the `models/` figure unstated; under the same reading it was zero then too, so the conclusion stands.

**Amended 2026-09-26 (#166):** two roles recorded above moved, and the roster did not. The classification filter's containment predicate is now `RuleFinding.classified_as_any` in `models/rule_finding.py`, which the filter service calls, so `services/rule_finding.py` imports the vocabulary for the Filter Options alone and `models/rule_finding.py` for its column type and that predicate; the four consumers the #167 amendment lists are unchanged. And `classification_options` no longer receives stored entries. The column type is `Classification` in Python, its `process_result_value` validates each stored entry and drops an invalid one with a warning, and the Filter Options read passes its distinct entries through that type, so `classification_options` takes `Classification` instances and screens them against the closed token set alone, dropping a valid Classification no token names. `classifications_in` still screens raw axe tags, so the two reads no longer take the same kind of input; each still drops what the closed token set cannot name. The stored-shape mint listed above is gone: the predicate passes `Classification` values from `classifications_in`, and the column type binds each in the compact stored shape.

**Amended 2026-09-27 (#177):** `_tag_parsing.py`, which the #131-review entry above leaves owning axe tag syntax, no longer exists. #177 folded it into `schemas/axe_payload.py`, so a rule's Category and WCAG Criteria are now read out of its tags inside the Axe Boundary module, beside the rule they are read for ([ADR 0009](0009-axe-payload-pydantic-boundary.md)'s 2026-09-27 amendment). That module already imported `classifications_in` from `models/classification.py` and is one of the four consumers the #167 amendment lists, so the roster is unchanged. The line between syntax and vocabulary stands: the syntax reads stay in the boundary module, and `models/classification.py` keeps the charter the #131-review entry closes.
