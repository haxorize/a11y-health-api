# Prose documents soft-wrap, one line per paragraph

> **Amended by [ADR 0041](0041-prose-spells-american-with-three-carve-outs.md):** frontmatter is exempt from the one-line rule below, though the spelling standard still governs it.

Every markdown document in the repo keeps one line per paragraph, bullet, or blockquote and lets the editor wrap: `docs/`, `DOMAIN.md`, `README.md`, `CLAUDE.md`, and the skills under `.claude/skills/`. Code prose keeps its 80-column wrap under `W505` and `tests/test_prose_shape.py`, and that is the split: a docstring is read in an editor beside 120-column code, while a document is read rendered, where a hard wrap changes nothing. Hard wrap was rejected because it left the repo with two conventions (the skills, glossary, and README soft-wrapped; the ADRs and `docs/architecture.md` hard-wrapped) and because the skill convention already forces soft wrap on the 6 repo skills through its line cap. This reverses commit 6ccacbc, which rewrapped `docs/architecture.md` at 80 columns as a whitespace-only change one day before this record. Accepted cost: unwrapping the 39 earlier ADRs and 3 solution docs resets `git blame` on the docs tree to one commit, paid once. — amended: see Amendments 2026-09-12

The check is a markdown paragraph rule in `tests/test_prose_shape.py` that fails a paragraph split across lines under any of the paths above; the whole-repo audit's fix pass adds it, and until then this record is the authority. — amended: see Amendments 2026-09-12

Revisit when: a markdown formatter that reflows on save joins the toolchain, or a reviewer needs line-granular diffs on a document often enough to count.

## Amendments

- **2026-09-12 (#142)** — The check landed, so this record is no longer the authority standing in for it: the rule is `markdown_continuations` and `test_no_markdown_block_spans_more_than_one_line` in `tests/test_prose_shape.py`. Its walk is every tracked `.md` rather than the five roots named above — currently the same set, but a document under a new directory is governed the day it lands rather than the day someone extends a list.
- **2026-09-12 (#142)** — **The blockquote clause is enforced, and the hard break is what makes it enforceable.** Consecutive `>` lines are the one shape a block marker cannot judge, because an ask block writes every quoted line with its own `>`. The rule reads the markdown hard break — two trailing spaces, or a backslash — as the author saying the line ends there, so a quoted line under one carrying no break is a wrapped quote. A bare `>` separates two quoted paragraphs and continues neither. Seventy-five hard-wrapped continuation lines in the amendment banners of ADRs 0009, 0011, 0034, 0035 and in `docs/architecture.md` were joined when the rule landed; the banners are the highest-churn lines in the tree, which is where line-granular diffs were the point.
- **2026-09-12 (#142)** — **Frontmatter is exempt from this rule.** A `description:` is one YAML line no editor can reflow, so the one-line rule never reads it, while ADR 0041's spelling standard does. The region function both markdown rules share takes the difference as an argument at each call site.
- **2026-09-12 (#142)** — **"Paid once" is what `.git-blame-ignore-revs` buys; without it the cost recurs forever.** The reflow landed as its own whitespace-only commit, every file token-identical to its parent, and that SHA is the file's one entry. Wired with `git config blame.ignoreRevsFile .git-blame-ignore-revs` (named in `CLAUDE.md`, since the setting is per clone), a blame over `docs/` attributes 0 lines to the reflow instead of 324. Git ignores a SHA in that file that no longer resolves without saying so, which is why the entry was written only after the split settled.
- **2026-09-12 (#142)** — The rejected-alternative rationale above overstated its own premise. "The skills, glossary, and README soft-wrapped" was not true of the tree the record was written against: `README.md` held two hard-wrapped paragraphs and `.claude/skills/testing/SKILL.md` held one, and the fix pass reflowed all three. The conclusion stands on the remaining ground — one convention beats two — but a reader reopening the wrap question should not weigh the rejected option against evidence that did not hold.
- **2026-09-12 (#147)** — **The `.git-blame-ignore-revs` amendment above is wrong on both of its numbers, and right on what they were for.** A blame over `docs/` with the ignore file wired attributes 24 lines to the reflow, not 0, and 317 without it, not 324; measured with `git blame -l --line-porcelain` over `git ls-files docs/`, and with `--no-ignore-revs-file` for the second, since `-c blame.ignoreRevsFile=/dev/null` silently keeps applying the repo's setting. All 24 are blank lines, which the heuristic cannot reattribute, so **no prose line blames to the reflow** and the claim the amendment was making holds. The 324 had already drifted to 317 six days later, because the amendments of #146 replaced reflow-attributed lines with their own — which is [ADR 0041](0041-prose-spells-american-with-three-carve-outs.md)'s rule against writing a count no check re-measures, applied to this record: the durable statement is the one about prose lines, and a total over a tree that changes is not.
