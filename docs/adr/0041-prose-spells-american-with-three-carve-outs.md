# Prose spells American, and three carve-outs say what is not prose

Every word this repo writes as prose takes the American form. The word list is not this record's to hold: it is `british_words` in the skills repo's `scripts/lint-skills.sh`, and this standard is the spelling bullet of that repo's ADR 0077 applied here, so a word joins or leaves the list there and this repo copies it. The check is a word-list test in `tests/test_prose_shape.py` that walks `git ls-files` and holds the list as a `BRITISH_WORDS` constant copied from that file; issue #142 adds it, and until then this record is the authority. — amended: see Amendments 2026-09-12, 2026-09-27

Three carve-outs, because the standard governs prose and most of what a word scan reaches is not prose. A form inside a code span or a URL is exempt and is stripped before the lookup, since a state value, an upstream identifier, or a vendor path is not this repo's to spell. A form that some other system matches by string is exempt only through a roster entry naming the consumer that requires it: `asyncio.CancelledError` at `tests/cli/conftest.py:144` is CPython's name, reached by import, and flipping it would break the import rather than fix the spelling. An entry with no named consumer is a word someone did not want to change, which is the thing the standard exists to settle. — amended: see Amendments 2026-09-12

The alternative was to spell each file the way its source spells it and check nothing, which a repo living off British-sourced ports would rationally pick, because the flip makes every later diff against such an upstream noisier for good. That cost is accepted here as ADR 0077 accepted it. Amending ADR 0018 to keep one house-style home was rejected: 0018 is about where comprehension lives, and orthography is a separate question that would sit inside it unread.

Revisit when: this repo starts carrying prose it does not own, at which point the roster grows faster than the standard is worth.

## Amendments

- **2026-09-12 (#142)** — The check landed as `test_prose_spells_american` in `tests/test_prose_shape.py`, holding `BRITISH_WORDS` copied from `british_words`, so this record is no longer the authority standing in for it. Building it turned up one more carve-out, one clarification of where ADR 0040's rule stops, and one repair to the roster; the third carve-out is why the title and the slug now say three. **A file format with no prose extractor yields no prose.** The walk reaches every tracked file, and only `.py` and `.md` have an extractor, the first keeping comments and docstrings while blanking every other literal, the second keeping the body while blanking fenced code. Neither count is written here: a tracked-file total and a word-list length both go stale on the next file or word added, with no check that would catch either, and the calibration comment in the module dropped its own count for exactly that reason. The alternative was to read every format and excuse what it turned up, which would have put `uv.lock`, `openapi.json`, and a captured axe payload fixture in front of the standard and left a roster entry as the only way to quiet each one; that inverts the roster from a narrow escape hatch into the mechanism, which is the failure the paragraph above exists to prevent. **Frontmatter is spelled but not wrapped** — a clarification of ADR 0040's reach rather than a carve-out of this record's, since it declares frontmatter *is* prose the standard governs. It is the one place this record and [ADR 0040](0040-prose-documents-soft-wrap-one-line-per-paragraph.md) part company: a skill's `description:` is prose a person reads, so the standard governs it, while it is also one YAML line no editor can reflow, so 0040's one-line rule cannot. Both markdown rules now read one region function that takes the difference as an argument at each call site, because the two guards each keeping a private answer is how the wrap rule came to skip frontmatter while the spelling rule read it. **The roster is keyed by file and word, not by the word.** 0041 above already named the site alongside the consumer; the first implementation kept only the consumer, and a bare key excuses a form everywhere — the single `Cancelled` entry let the everyday spelling of that word through in every document in the repo, which is the "word someone did not want to change" this record was written to catch. The alternative was a line-number key, rejected because it would red on every edit above the entry and still sleep through the form moving to another file; the file key carries no line and so does neither.
- **2026-09-12 (#142)** — **Upstream's two exemption mechanisms are not adopted here.** ADR 0077 settles exemption twice — a repo-wide flip with `global/hooks/**` and `scripts/**` excluded as whole trees, and a line-scoped `<!-- spelling-exempt: WORD -->` marker — and this repo takes neither. The extractor-per-format rule and the `DELIBERATE_BRITISH` roster stand in their place. The consequence worth knowing: an upstream marker is inert here, and the marker line is itself prose this rule reads, so a document synced in carrying one is flagged on the marker's own word. The escape is a roster entry keyed to that path, which this repo owns and may edit — so the two repos can be satisfied at once, but not by the same mechanism.
- **2026-09-12 (#142)** — **A comment extractor for the three config formats this repo writes prose in is a narrower question than the one the rule above settled, and it is still open.** "A file format with no prose extractor yields no prose" was decided against reading *every* format, on the ground that doing so would put `uv.lock` and `openapi.json` in front of the standard and invert the roster from an escape hatch into the mechanism. That argument is sound and stands. It does not reach an extractor that reads only `#` comments in `.toml`, `.yml`, and shell files, because such an extractor never yields a line from `uv.lock` or `openapi.json` — neither format has comments, and the second is not even a candidate. Today the rationale comments in `pyproject.toml` (18 lines), `.github/workflows/ci.yml` (25 lines), and `.githooks/pre-commit` (1 line) are prose this repo owns and are outside the standard. No live offender exists: a scan of every tracked file with the raw word list, bypassing the extractor, found the only British forms outside the governed set are the guard's own `BRITISH_WORDS` block and its test fixtures. So this is a latent gap, recorded here rather than filed, and the cost of closing it is one extractor per format against a body of prose that is currently clean.
- **2026-09-19 (#152 review)** — **The latent gap in the third 2026-09-12 entry is wider than that entry says, and its counts are withdrawn rather than restated.** The ungoverned prose is now the `#` comments in `pyproject.toml`, `.github/workflows/ci.yml`, `.githooks/pre-commit`, the `Makefile`, and every shell script under `scripts/`, so the formats an extractor would need are four (TOML, YAML, shell, and make), not three. The entry's per-file line counts were exact when written and went stale because nothing measures them; no count replaces them here, since a number in prose with no guard behind it is stale by the next comment. The roster of formats is what this record keeps, and the size is what the extractor would report. The entry's argument stands, and a scan of those comments against `BRITISH_WORDS` on this date still found no live offender.
- **2026-09-27** — **The copy is two values, not one.** The skills repo added `british_prefixes` beside `british_words` in the same file, and its header now says that copying the list alone is the weaker check. `tests/test_prose_shape.py` holds it as `BRITISH_PREFIXES`, and a sync copies both. A token fires when it is a listed word, or when one prefix is followed by a whole listed word: `untotalled` fires, `reprogram` does not, and only one prefix is stripped, so `reunlabelled` passes as it does upstream. The two-letter check upstream runs before its prefix loop is not copied, since it only makes the check faster and never changes a result.
