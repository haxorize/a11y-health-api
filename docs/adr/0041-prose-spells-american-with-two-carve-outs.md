# Prose spells American, and two carve-outs say what is not prose

Every word this repo writes as prose takes the American form. The word list is not this record's to hold: it is `british_words` in the skills repo's `scripts/lint-skills.sh`, and this standard is that repo's ADR 0077 applied here, so a word joins or leaves the list there and this repo copies it. The check is a word-list test in `tests/test_prose_shape.py` that walks `git ls-files` and holds the list as a `BRITISH_WORDS` constant copied from that file; issue #142 adds it, and until then this record is the authority. — amended: see Amendments 2026-09-12

Two carve-outs, because the standard governs prose and most of what a word scan reaches is not prose. A form inside a code span or a URL is exempt and is stripped before the lookup, since a state value, an upstream identifier, or a vendor path is not this repo's to spell. A form that some other system matches by string is exempt only through a roster entry naming the consumer that requires it: `asyncio.CancelledError` at `tests/cli/conftest.py:140` is CPython's name, reached by import, and flipping it would break the import rather than fix the spelling. An entry with no named consumer is a word someone did not want to change, which is the thing the standard exists to settle. — amended: see Amendments 2026-09-12

The alternative was to spell each file the way its source spells it and check nothing, which a repo living off British-sourced ports would rationally pick, because the flip makes every later diff against such an upstream noisier for good. That cost is accepted here as ADR 0077 accepted it. Amending ADR 0018 to keep one house-style home was rejected: 0018 is about where comprehension lives, and orthography is a separate question that would sit inside it unread.

Revisit when: this repo starts carrying prose it does not own, at which point the roster grows faster than the standard is worth.

## Amendments

- **2026-09-12 (#142)** — The check landed as `test_prose_spells_american` in `tests/test_prose_shape.py`, holding `BRITISH_WORDS` as 260 words copied from `british_words`, so this record is no longer the authority standing in for it. Building it turned up two more carve-outs and one repair to the roster, and the title's count is the pre-amendment one. **A file format with no prose extractor yields no prose.** The walk reaches every tracked file — 234 readable ones — and only `.py` and `.md` have an extractor, the first keeping comments and docstrings while blanking every other literal, the second keeping the body while blanking fenced code. The alternative was to read every format and excuse what it turned up, which would have put `uv.lock`, `openapi.json`, and a captured scan fixture in front of the standard and left a roster entry as the only way to quiet each one; that inverts the roster from a narrow escape hatch into the mechanism, which is the failure the paragraph above exists to prevent. **Frontmatter is spelled but not wrapped.** It is the one place this record and [ADR 0040](0040-prose-documents-soft-wrap-one-line-per-paragraph.md) part company: a skill's `description:` is prose a person reads, so the standard governs it, while it is also one YAML line no editor can reflow, so 0040's one-line rule cannot. Both markdown rules now read one region function that takes the difference as an argument at each call site, because the two guards each keeping a private answer is how the wrap rule came to skip frontmatter while the spelling rule read it. **The roster is keyed by file and word, not by the word.** 0041 above already named the site alongside the consumer; the first implementation kept only the consumer, and a bare key excuses a form everywhere — the single `Cancelled` entry let the everyday spelling of that word through in every document in the repo, which is the "word someone did not want to change" this record was written to catch. The alternative was a line-number key, rejected because it would red on every edit above the entry and still sleep through the form moving to another file; the file key carries no line and so does neither.
