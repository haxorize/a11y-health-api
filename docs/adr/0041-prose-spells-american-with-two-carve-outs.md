# Prose spells American, and two carve-outs say what is not prose

Every word this repo writes as prose takes the American form. The word list is not this record's to hold: it is `british_words` in the skills repo's `scripts/lint-skills.sh`, and this standard is that repo's ADR 0077 applied here, so a word joins or leaves the list there and this repo copies it. The check is a word-list test in `tests/test_prose_shape.py` that walks `git ls-files` and holds the list as a `BRITISH_WORDS` constant copied from that file; issue #142 adds it, and until then this record is the authority.

Two carve-outs, because the standard governs prose and most of what a word scan reaches is not prose. A form inside a code span or a URL is exempt and is stripped before the lookup, since a state value, an upstream identifier, or a vendor path is not this repo's to spell. A form that some other system matches by string is exempt only through a roster entry naming the consumer that requires it: `asyncio.CancelledError` at `tests/cli/conftest.py:140` is CPython's name, reached by import, and flipping it would break the import rather than fix the spelling. An entry with no named consumer is a word someone did not want to change, which is the thing the standard exists to settle.

The alternative was to spell each file the way its source spells it and check nothing, which a repo living off British-sourced ports would rationally pick, because the flip makes every later diff against such an upstream noisier for good. That cost is accepted here as ADR 0077 accepted it. Amending ADR 0018 to keep one house-style home was rejected: 0018 is about where comprehension lives, and orthography is a separate question that would sit inside it unread.

Revisit when: this repo starts carrying prose it does not own, at which point the roster grows faster than the standard is worth.
