# The onboarding CLI is five concern modules over one error base

Decided 2026-08-05 in [#132](https://github.com/haxorize/a11y-health-api/issues/132): the `a11y` onboarding CLI is a package of five concern modules, not the three seams the story asked for, over one shared error base. `_errors` holds `CliError` alone, so no module imports a sibling merely to declare a failure; `_scan` reads a scan directory and never learns the API exists; `_client` is one function per HTTP request and never reads a directory or prints; `_operations` sequences the two into `ingest` and `import`, holding everything that needs disk and API at once; `_terminal` parses argv, prints, and chooses an exit code. The story's three named seams are unchanged — `_errors` and `_operations` sit below and between them, which is the whole departure.

`_scan` and `_client` never import each other, and that constraint is load-bearing rather than tidy. It is what keeps the two peers under `_operations` instead of a chain, and it is what lets a failure occurring before the first request be driven against a client that fails the test if any request is made at all — the `no_server` double at `tests/cli/conftest.py:17`. A regression that moved a check after the lookup would create a Scan Run and then fail, leaving it Pending and unscored; against a real client that regression passes silently, and against `no_server` it fails at the transport. The constraint is held today by module prose and by that double, not by an import-graph test, so crossing it costs a guard nobody has written.

Every failure an operator can cause is a named subclass of `CliError`, and `CliError` is the only error type `main()` catches. Anything else keeps its traceback, because anything else is a defect. `main()` carries a second `except` for `KeyboardInterrupt`, which is neither an operator error nor a defect and for which a traceback served nobody. The audit of the generic-error-capable calls, and which were wrapped, caught in place, or found unreachable on operator input, is [#132](https://github.com/haxorize/a11y-health-api/issues/132)'s AC2 and stays there rather than being copied here.

The implementing commit deliberately wrote no record, on the grounds that the decisions were cheap to reverse and the rationale belonged in module prose where the next contributor would look. That reasoning held while `docs/architecture.md` carried the full package map. It stops holding once the map is cut to one sentence, because the sentence and the CLI package headers would then cite each other and nothing would hold the why. This record is the keeper the architecture sentence cites: [#148](https://github.com/haxorize/a11y-health-api/issues/148) cuts the map to one sentence naming this record by number. The CLI package headers do not cite it; the module prose stays as the local statement of each concern. — amended: see Amendments 2026-09-19

Revisit when: a sixth concern joins the package, or the constraint keeping `_scan` and `_client` from importing each other is crossed.
