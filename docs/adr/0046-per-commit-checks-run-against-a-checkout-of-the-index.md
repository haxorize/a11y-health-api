# Per-commit checks run against a checkout of the index, in a throwaway worktree

`.githooks/pre-commit` scans the staged changes for secrets in the developer's own repo, then builds a detached worktree from the staged tree and runs lint, the OpenAPI staleness check, and the full suite inside it. What the checks measure is therefore the commit being made and nothing else: an unstaged edit and an untracked file both stay out of the run. Two properties depend on this and neither is cosmetic. A hook that measured the working tree passes a commit whose staged half is broken, because the unstaged half completed it. And `CLAUDE.md` promises that every commit in a multi-commit split passes standing alone — a promise the hook now enforces rather than assumes, which is what makes a split with a broken intermediate commit impossible to create rather than merely discouraged.

The index the hook reads is not always `.git/index`: `git commit -a` builds the tree in `.git/index.lock` and `git commit <paths>` in a `next-index-<pid>.lock` beside it, holding it while the hook runs. The hook copies whichever one git named through `GIT_INDEX_FILE`, writes a tree from the copy, and wraps it in a commit object, because `worktree add` takes a commit-ish and checking one out seeds the new worktree with the staged content. The copy is why the developer's real index is never written. — amended: see Amendments 2026-09-19

One deliberate exception to "the checks see only what is committed": `.env` is gitignored, so it is absent from the checkout, and the hook copies it in. Without it the checks would run against `config.py`'s defaults rather than the developer's settings, and would test a different database than the developer's own `make test` does. — amended: see Amendments 2026-09-19 The OpenAPI stage is insulated from that copy separately — `scripts/export_openapi.py` generates from the declared settings rather than the environment, so a local `VERSION` cannot make the committed spec look stale.

Accepted cost: a commit pays a secret scan, a dependency sync into a fresh checkout, a second full app import for the OpenAPI stage, and the suite — measurably more than `make test` alone. Temp paths carry the run's PID and the sweep skips a PID that is still alive, so two commits in two terminals cannot delete each other's checkout. — amended: see Amendments 2026-09-19

Considered and rejected:

- **Reverting the tree to the index and restoring a saved patch afterwards:** leaves untracked files in place, so an untracked module a committed file imports still carries the run, and a `git rm --cached` is checked with the file it deletes still on disk. Moving untracked files aside too closes that, but a run killed outright then leaves them somewhere the developer has to be told about. Both variants write the developer's tree and rely on putting it back.
- **`git stash push --keep-index`:** worse than either. A pop over one file that is both staged and unstaged conflicts every time and leaves the index unmerged, destroying the staged selection about to be committed.
- **Running the checks in the working tree, as the hook did before:** the cheapest option and the one this record replaces. It cannot distinguish a green commit from a green tree, which is the whole question a pre-commit check is asked.
- **`git worktree remove` instead of `rm -rf` in cleanup:** the OpenAPI stage regenerates inside the worktree, and `remove` refuses a dirty one. — amended: see Amendments 2026-09-19

The two Alembic stages stay in CI rather than the hook, because each needs a live Postgres to upgrade and downgrade against and a hook that reached for a developer's database would either rewrite it or fail on a machine that has none. See [`docs/operating.md`](../operating.md) ("How a change is checked") for the three gates in the order a change meets them. — amended: see Amendments 2026-09-26 (#172)

## Amendments

- **2026-09-19 (#152 review)** — **The accepted cost was under-counted.** A commit pays a secret scan, a checkout of the index, a dependency sync into it, the full lint stage (`ruff check`, `ruff format --check`, `ty`, `deptry`), a second full import of the application for the OpenAPI stage, and the suite. The list above left out the checkout and the lint stage, in the sentence whose purpose is budgeting.
- **2026-09-19 (#152 review)** — **The worktree isolates every file and not the test database, which two concurrent runs would otherwise share; `tests/conftest.py` isolates that one separately.** Each suite run creates its own database, named for the pytest process's PID, not the hook's: the hook's temp paths carry the hook shell's `$$`, and the two never match. The mechanism and its record are [ADR 0011](0011-transactional-rollback-test-isolation.md)'s 2026-09-19 amendment. It also narrows the `.env` exception above: with a per-run database, the hook's checks and the developer's own `make test` never share a database, `.env` or not. What the copy still carries is which server, which credentials, and which template name the per-run database is derived from, so without it the checks would reach `config.py`'s defaults for all three.
- **2026-09-19 (#152 review)** — **The rejected `git worktree remove` bullet gave a false reason.** The OpenAPI stage does not regenerate inside the worktree; it writes to a `mktemp` path. The real reason is that `uv sync` creates `.venv/` inside the worktree and the suite leaves `__pycache__` behind, and `remove` refuses a dirty one. The decision stands; a reader who checked the old premise, found it false and switched to `remove` would break every commit.
- **2026-09-19 (#152 review)** — **The half that builds the checkout is now [`scripts/staged_worktree.sh`](../../scripts/staged_worktree.sh), not lines in the hook, so the two claims in the first paragraph are checkable.** `tests/test_staged_worktree.py` drives it over a scratch repository holding a committed file, a staged edit, an unstaged edit on top of it, and an untracked file, and asserts what reaches the checkout and that neither the working tree nor the index moved. Inline, checking either claim meant making commits in this repository and reading what happened, which is not a check anyone runs. The hook keeps the stale-run sweep, the traps, and cleanup.
- **2026-09-26 (#172)** — **Only one Alembic stage stays in CI now: the `migration-drift` job's autogenerate check, for the reason above.** The roundtrip moved into the suite as `test_the_revisions_above_the_floor_reverse` in `tests/migrations/test_downgrade_floor.py`, which upgrades and downgrades a per-run database of its own rather than `DATABASE_URL`'s, so the hook runs it with the rest of the suite. The accepted cost grows by that roundtrip: a child Alembic interpreter migrating a second per-run database on every commit. The mechanism is [ADR 0011](0011-transactional-rollback-test-isolation.md)'s 2026-09-26 (#172) amendment.
